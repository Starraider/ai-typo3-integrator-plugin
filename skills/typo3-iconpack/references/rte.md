# RTE integration and persistence

For TYPO3 12+ use CKEditor 5. The `Iconpack` plugin handles selection, insertion, editing and model conversion for webfont/SVG icons; CSS and a toolbar string alone cannot implement that behavior. Keep the project's existing RTE preset and imports unless a change is required.

## Automatic configuration

The simplest setup uses extension setting `EXTENSIONS.iconpack.autoConfigRte = 1` and installs an actual provider. Iconpack's editor event listener adds its supplied YAML configuration to the editor. Keep `rteSvg = 1` for SVG rendering, and configure the provider's `preferredRenderTypes.backend.rte` for the desired editor representation. `autoAddAssets` concerns frontend CSS, not enabling the toolbar button.

With automatic setup, do not also import `IconpackConfig-v12.yaml` or add a duplicate button. Check custom preset loading and toolbar exclusions when the automatic button is absent. [Editor configuration listener](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Classes/EventListener/IconpackPrepareConfigurationForEditor.php).

## Manual CKEditor 5 preset

When the project needs explicit preset control, disable only `autoConfigRte` in extension configuration; keep the provider, persistence integration and sanitizer active. In `packages/sitepackage/Configuration/RTE/Icons.yaml`, preserve the site's normal preset imports, then import the supplied Iconpack config:

```yaml
imports:
  - { resource: 'EXT:rte_ckeditor/Configuration/RTE/Default.yaml' }
  - { resource: 'EXT:iconpack/Configuration/RTE/IconpackConfig-v12.yaml' }
```

If the owning project already imports a different complete preset, use that in place of `Default.yaml`. The `v12` filename is also used by the researched extension for TYPO3 13/14; it refers to the CKEditor 5 branch.

Alternatively, replace the second import with its explicit plugin and button configuration, adding the site's existing toolbar items as necessary:

```yaml
imports:
  - { resource: 'EXT:rte_ckeditor/Configuration/RTE/Default.yaml' }
editor:
  config:
    contentsCss:
      - 'EXT:iconpack/Resources/Public/Css/Backend/CKEditor.min.css'
    importModules:
      - module: '@quellenform/iconpack-ckeditor.js'
        exports: ['Iconpack']
    toolbar:
      items:
        - bold
        - italic
        - link
        - '|'
        - Iconpack
        - undo
        - redo
```

These are alternatives; do not load the module twice. Merge existing toolbar items instead of reducing a working toolbar without instruction. The module alias is supplied by `EXT:iconpack/Configuration/JavaScriptModules.php`; do not add a fake CDN script or a duplicate site-package alias. [Supplied CKEditor YAML](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Configuration/RTE/IconpackConfig-v12.yaml), [module mapping](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Configuration/JavaScriptModules.php).

The exact button/plugin contract is: exported plugin `Iconpack`, toolbar item `Iconpack` as in the shipped YAML, UI component/command `iconpack` internally. The supplied `IconpackUI` defines its ButtonView and invokes `editor.execute('iconpack')` to open the pack picker. A Page TSconfig `buttons.iconpack` entry cannot create this plugin. A custom plugin is unnecessary for the normal insertion button. [Button and command implementation](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Build/Sources/TypeScript/v12/CKEditor/plugin.ts).

For **webfont** rendering, the selected provider CSS must reach the editable content and its font URLs must load. The extension includes provider CSS in the backend automatically. If a custom editor integration needs explicit content CSS, append these to `editor.config.contentsCss` in the manual preset:

```yaml
editor:
  config:
    contentsCss:
      - 'EXT:iconpack/Resources/Public/Css/Backend/CKEditor.min.css'
      - 'EXT:iconpack_fontawesome/Resources/Public/Vendor/fa7/css/fontawesome.min.css'
      - 'EXT:iconpack_fontawesome/Resources/Public/Vendor/fa7/css/solid.min.css'
      - 'EXT:iconpack_fontawesome/Resources/Public/Vendor/fa7/css/regular.min.css'
      - 'EXT:iconpack_fontawesome/Resources/Public/Vendor/fa7/css/brands.min.css'
```

Include only the styles enabled/used in this editor. This block is an addition to the complete preset, not a separate second `editor:` key in the same YAML document. Font Awesome classes such as `fas fa-house` are generated by the pack renderer; let the picker create the markup with `data-iconfig`.

For **SVG**, use `rteSvg = 1` plus `backend.rte: 'svgInline,svgSprite,webfont,svg'` in provider YAML. Iconpack's CKEditor schema/converters permit the appropriate widget elements. `svgInline` reads individual SVG files, `svgSprite` references a symbol, and `svg` produces an `<img>` from an individual SVG. Do not paste arbitrary unfiltered SVG into the editor as a substitute.

## Register and assign the preset

In `packages/sitepackage/ext_localconf.php`:

```php
<?php

defined('TYPO3') || die();

$GLOBALS['TYPO3_CONF_VARS']['RTE']['Presets']['site_icons']
    = 'EXT:sitepackage/Configuration/RTE/Icons.yaml';
```

For TYPO3 12+, add Page TSconfig to the site's existing `packages/sitepackage/Configuration/page.tsconfig` (or its activated set's `page.tsconfig` on TYPO3 13+):

```typoscript
RTE.default.preset = site_icons
RTE.config.tt_content.bodytext.preset = site_icons
```

Use the global assignment only if all editor fields should use it. Field-specific assignments and TCA presets can override the global one; inspect effective Page TSconfig for the edited page. A custom field's TCA config can set a default directly:

```php
'config' => [
    'type' => 'text',
    'enableRichtext' => true,
    'richtextConfiguration' => 'site_icons',
],
```

For TYPO3 11, explicitly load Page TSconfig using the project's existing `ExtensionManagementUtility::addPageTSConfig()` convention; do not assume modern automatic file loading.

## Preserve placeholder attributes

Iconpack ships this Page TSconfig rule in `EXT:iconpack/Configuration/page.tsconfig`:

```typoscript
RTE.default.proc.HTMLparser_db.tags.span.allowedAttribs := addToList(data-iconfig,id,name,class,style,alt,title,lang,dir)
```

If custom field-specific processing overrides the default and loses icon attributes, add the needed attributes at that same scope, for example:

```typoscript
RTE.config.tt_content.bodytext.proc.HTMLparser_db.tags.span.allowedAttribs := addToList(data-iconfig,class,title)
```

Inspect effective processing first and keep existing allowed attributes. This rule preserves metadata; it does not install an editor plugin or allow arbitrary SVG. [Shipped Page TSconfig](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Configuration/page.tsconfig).

## Persistence and frontend reconstruction

The round trip is:

1. The plugin inserts a webfont/span, SVG widget or image containing `data-iconfig`.
2. Iconpack's PHP transformation normalizes recognized icons into a persistent `<span data-iconfig="..."></span>` representation with permitted attributes. The stored placeholder is expected to look different from the editor SVG.
3. On output, `Quellenform\Iconpack\UserFunc\ParseFuncRte->replaceIcons` reconstructs markup using frontend rendering preferences. The editor's rendering preferences may differ.
4. TYPO3's parse function and Iconpack's sanitizer must allow the reconstructed representation; frontend CSS/fonts or sprite URLs must resolve.

An illustrative stored placeholder is `<span data-iconfig="fa7:solid,house"></span>`; actual output may retain classes/options. Preserve the exact stored iconfig, including style and options. [Persistence parser](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Classes/Html/IconpackHtmlParser.php).

Iconpack 1.5.5 registers an `RteHtmlParser` XCLASS below TYPO3 13.3 and an event listener for persistence in newer TYPO3, and sets the default HTML sanitizer to `Quellenform\Iconpack\Sanitizer\IconpackHtmlSanitizer`. Inspect existing XCLASS/default-sanitizer customizations before installation: only one class can occupy each global slot. Resolve competing integrations explicitly; do not overwrite security filtering with a permissive workaround. [Boot configuration](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/ext_localconf.php), [persistence event listener](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Classes/EventListener/IconpackBeforeTransformTextForPersistence.php).

In Fluid, render persisted bodytext through the site's configured parse function:

```html
<f:format.html parseFuncTSPath="lib.parseFunc_RTE">{data.bodytext}</f:format.html>
```

The supplied Iconpack setup installs `lib.parseFunc_RTE.nonTypoTagUserFunc`. Confirm later imports have not replaced it. Never use `f:format.raw` as a fix for a stripped RTE icon.

For an existing custom RTE field that cannot use the normal transform, the supported processor can act on the rendering content object's record data:

```typoscript
lib.contentElement.dataProcessing {
  90 = Quellenform\Iconpack\DataProcessing\IconpackProcessor
  90 {
    fieldName = tx_sitepackage_bodytext
    fieldType = rte
  }
}
```

Choose a free processor number and attach it to the actual content object, not blindly to `lib.contentElement` if that object is unused. It transforms `data.<fieldName>` in place; it does not create an `as` variable or query Extbase records. When parsing a pre-transformed **sprite-only** field, a narrowly scoped parse-function copy can allow the necessary elements without changing all RTE fields:

```typoscript
lib.siteIconParseFunc < lib.parseFunc_RTE
lib.siteIconParseFunc.allowTags := addToList(svg,use)
```

```html
<f:format.html parseFuncTSPath="lib.siteIconParseFunc">{data.tx_sitepackage_bodytext}</f:format.html>
```

Inline SVG may additionally require `g,path,line,polyline,polygon,rect,circle,ellipse,defs,title,desc` and relevant attributes, depending on the actual assets and parser. Inspect the exact lost tags/attributes; let the extension sanitizer remain authoritative. The normal placeholder transform is preferable to widening generic parsing rules. [Processor implementation](https://github.com/quellenform/t3x-iconpack/blob/1.5.5/Classes/DataProcessing/IconpackProcessor.php).

## Legacy CKEditor 4 on TYPO3 10/11

Only for maintaining an existing legacy site, use the extension's `EXT:iconpack/Configuration/RTE/IconpackConfig-v11.yaml`, or its `IconpackConfig-v11-svg.yaml` variant with SVG enabled. The external plugin is `EXT:iconpack/Resources/Public/JavaScript/v11/CKEditor/plugin.js`, configured under `editor.externalPlugins.iconpack`; CKEditor 4 uses `editor.config.extraPlugins: [iconpack]`. Import the supplied version-matched file rather than copying CKEditor 5 syntax. Its allowed-content rules retain `data-iconfig`. Neither CKEditor 4 `externalPlugins` nor a `buttons.*` TSconfig rule substitutes for CKEditor 5 `importModules`.

## Inspect stored content without changing it

Use the project's database client or a read-only database session and replace `123` with the test content record UID:

```sql
SELECT uid, bodytext FROM tt_content WHERE uid = 123;
```

Look for the inserted `data-iconfig` and its style/options. Inspect custom RTE fields in their actual table/column. Do not rewrite saved HTML as a troubleshooting shortcut.

## Required verification

Flush caches and reopen the actual target field as the intended editor role. Insert a solid icon and a brand icon if enabled; save, close, reopen, edit the icon, save again, and view the frontend. Inspect stored `data-iconfig` with a read-only query or record inspection. Confirm the frontend transforms placeholders, and test cold-cache and warm-cache requests. Do not report completion based only on a visible toolbar button.
